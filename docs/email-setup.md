# إعداد بريد المصادقة (Supabase + Resend)

هذه إعدادات تُضبط في لوحة Supabase ولا يمكن ضبطها من الكود. الترتيب أدناه مقصود.

## ١) أطفئ «Confirm email» — إلزامي

`Authentication → Sign In / Providers → Email → Confirm email = Off → Save`

سببان لا غنى عنهما:

1. **حسابات الجوّال لا بريد لها.** التسجيل برقم جوّال يُنشئ حسابًا ببريد داخلي
   `<رقم>@phone.lageetha.app` (انظر `src/lib/identity.js`). مع تفعيل التأكيد يحاول
   Supabase إرسال رسالة إلى هذا النطاق غير الموجود، فيفشل التسجيل بالجوّال دائمًا.
2. **الرسائل المرتدة تُسقط سمعة المُرسِل.** أي خدمة بريد — ومنها Resend — تعاقب
   الحسابات ذات نسبة الارتداد العالية، وقد تُعلّق الحساب. إبقاء التأكيد مفعّلًا مع
   حسابات الجوّال يعني ارتدادًا مضمونًا عند كل تسجيل بجوّال.

بعد إطفائه لا تُرسَل أي رسالة عند التسجيل، ويختفي خطأ «تجاوزت حدّ رسائل التأكيد» فورًا.

## ٢) اربط Resend كخادم SMTP

خادم البريد المدمج في Supabase للتجربة فقط: لا يوصل الرسائل إلا إلى عناوين فريق
المشروع، وحدّه رسالتان في الساعة (وهو سبب الخطأ الذي ظهر). ربط SMTP خاص هو الطريق
الوحيد لرفع هذا الحدّ ولإيصال رسائل **استعادة كلمة المرور** إلى مستخدمين حقيقيين.

### أ) في Resend

1. `Domains → Add Domain` وأضف سجلات DNS التي يطلبها حتى تصبح الحالة **Verified**.
   - بلا نطاق موثّق لن تستطيع الإرسال إلا من `onboarding@resend.dev` وإلى بريدك أنت
     فقط — يكفي للتجربة، ولا يكفي لمستخدمين حقيقيين.
2. `API Keys → Create API Key` بصلاحية الإرسال، وانسخ المفتاح (`re_…`) فورًا؛ لا يظهر
   مرة أخرى.

### ب) في Supabase

`Project Settings → Authentication → SMTP Settings → Enable Custom SMTP`

| الحقل | القيمة |
|---|---|
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | مفتاح Resend (`re_…`) |
| Sender email | عنوان على نطاقك الموثّق، مثل `no-reply@your-domain.com` |
| Sender name | `لقيتها` |

### ج) ارفع الحدّ بعد الربط

`Authentication → Rate Limits → Rate limit for sending emails`

يبقى الحدّ المنخفض ساريًا حتى تغيّره يدويًا بعد ضبط SMTP.

## ٣) العناوين المسموح بالعودة إليها

`Authentication → URL Configuration`

- **Site URL**: عنوان التطبيق المنشور.
- **Redirect URLs**: أضف `http://localhost:5173/**` للتطوير.

التطبيق يمرّر `emailRedirectTo` عند التسجيل و`redirectTo` عند استعادة كلمة المرور
(`src/lib/api.js`)، وكلاهما يجب أن يكون ضمن هذه القائمة وإلا تجاهله Supabase.

## ما الذي يعتمد على البريد فعلًا؟

بعد إطفاء التأكيد، الاستخدام الوحيد للبريد هو **استعادة كلمة المرور**، وهي متاحة
لحسابات البريد فقط؛ من سجّل برقم جوّاله لا يملك بريدًا تُرسل إليه الرسالة، ويحتاج
تدخّل إدارة النظام لاستعادة حسابه.
